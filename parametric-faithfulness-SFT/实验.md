# DeepSeek-Revision SFT 参数忠实性实验协议

## 一、实验目的

本实验从原始 `Llama-3.2-3B-Instruct` 出发，只进行一次监督微调，研究 DeepSeek
修订过的学生推理轨迹是否能改善学生模型的参数忠实性。参数忠实性通过 Tutek
et al. (2025) 的 Faithfulness by Unlearning Reasoning Steps (`FUR`) 测量。

核心比较为：

| 名称 | 定义 |
| --- | --- |
| `Base LLaMA-3B` | 未进行任何本实验训练的原始学生模型 |
| `DeepSeek-Revision SFT` | 以 DeepSeek 修订后的 OpenBookQA train 推理为监督，对学生模型进行一次 `down_proj` LoRA-SFT 并合并后的模型 |

两者都在同一份独立 `OpenBookQA test` 问题上重新生成 reasoning，再分别对其自身
reasoning 运行 FUR。不存在将 base 的 CoT 直接交给 SFT 模型评价的情况。

## 二、独立性与本地资源

本实验运行目录：

```text
parametric-faithfulness-SFT/
```

目录内部保存并使用自己的资源：

```text
local_models/Llama-3.2-3B-Instruct/     # 原始模型副本
local_datasets/openbookqa/               # OpenBookQA 数据副本
artifacts/models/deepseek_revision_sft/  # SFT adapter 与合并模型
```

本实验不读取 `parametric-faithfulness-ToT/` 中已生成的 CoT、split 或结果文件。
已有目录只曾作为本地资源拷贝来源；拷贝完成后，执行路径全部位于本目录内。
运行环境固定为 Conda `faith`，启动脚本直接使用该环境的 Python；若出现缺包，
仅在这一环境中补充安装并记录依赖变动。

## 三、数据协议

### 3.1 训练数据

| 设置 | 值 |
| --- | --- |
| dataset | OpenBookQA |
| split | `train` |
| 总可用样本数 | `4957` |
| 默认候选样本数 | `2000` |
| 采样 seed | `1001` |
| student draft decoding | greedy, `temperature=0.0` |
| student draft max new tokens | `128` |
| student draft inference batch size | `32` |

流程：

1. 原始 LLaMA-3B 仅依据题目和选项生成 draft rationale。
2. DeepSeek 读取题目、选项和 draft rationale，对推理进行纠正或压缩。
3. DeepSeek 不接收 OpenBookQA gold answer。
4. 脚本在返回后用 gold answer 过滤 teacher 结果。
5. 合格的修订 rationale 成为唯一一次 SFT 的 completion。

### 3.2 Teacher 配置

| 设置 | 值 |
| --- | --- |
| provider | DeepSeek API |
| 默认 model | `deepseek-v4-pro` |
| thinking 模式 | `enabled`, `reasoning_effort=high` |
| completion 上限 | `4096` tokens（包括 thinking token） |
| 返回格式 | JSON：`rationale`, `answer` |
| rationale 句数 | `2-4` |
| rationale 单词数 | `20-80` |
| 显式答案字母泄漏 | 丢弃 |
| teacher answer 错误 | 丢弃 |
| API 失败/解析失败 | 记录并跳过，可恢复 |
| API 并发上限 | 首轮 `8`，错误重试轮 `4` |

API key 位于本地 `.env` 并被 `.gitignore` 排除；运行日志不会打印 key。
`deepseek-v4-pro` 已在正式运行前通过一次最小 API 可用性请求验证；所有正式
revision 行均需以 `teacher_model` 字段记录该模型名。
该模型在 thinking 模式下的内部 reasoning token 会占用 completion budget，因而
不使用原先的 `512` token 小预算，避免最终 JSON 在输出前被截断。

### 3.3 SFT 输入输出

SFT 输入：

```text
Human: Question: {question}

Choices:
(A): {option a}
(B): {option b}
(C): {option c}
(D): {option d}

Assistant: Let's think step by step:
```

SFT 输出：

```text
{DeepSeek revised rationale}
```

训练目标不包含答案字母，也不包含原 student draft。这保证评测时模型仍按 FUR
论文采用的两阶段方式：先输出 reasoning，再由独立答题 prompt 提取答案。

### 3.4 最终测试数据

| 设置 | 值 |
| --- | --- |
| dataset | OpenBookQA |
| split | `test` |
| test sampling seed | `1001` |
| target questions | `100` |
| specificity/retain questions | `20` |
| 合计 | `120` |
| manifest | `artifacts/splits/openbookqa_test_seed1001_n100_retain20.json` |

Base 与 SFT 模型共享题目清单，但必须分别生成自己的新 CoT。

## 四、一次 SFT 参数

原 FUR 论文没有提出“提高忠实性”的 SFT 训练算法，也没有报告本实验类型的 SFT
最优学习率。因此下表属于预注册式固定扩展设置，不声称是论文最佳值。

| 参数 | 值 |
| --- | --- |
| base model | `local_models/Llama-3.2-3B-Instruct` |
| precision | `bf16` |
| tuning method | LoRA-SFT |
| LoRA target modules | `down_proj` |
| LoRA rank | `32` |
| LoRA alpha | `64` |
| LoRA dropout | `0.05` |
| max sequence length | `512` |
| batch size per device | `2` |
| gradient accumulation steps | `16` |
| effective batch size | `32` |
| learning rate | `1e-4` |
| epochs | `1` |
| scheduler | cosine |
| warmup steps | 总 optimizer update steps 的 `3%` 四舍五入 |
| optimizer | `AdamW` |
| gradient checkpointing | enabled |
| seed | `1001` |

只选择 `down_proj` 进行 LoRA 的实验理由：FUR 的遗忘干预也只更新
`mlp.down_proj.weight`。将训练变化集中于该参数家族，可减少训练效果写入其它
模块而干预无法探测的结构混杂。

合并后的 SFT 模型位置：

```text
artifacts/models/deepseek_revision_sft/merged/Llama-3.2-3B-Instruct/
```

## 五、FUR 参数：严格沿用论文 OpenBookQA 最佳设置

下面的参数是本实验中复用论文/官方代码口径的部分。论文给出的
`Llama-3.2-3B-Instruct + OpenBookQA` 最佳 FUR learning rate 为 `3e-05`。

| 参数 | 值 |
| --- | --- |
| intervention method | `NPO + KL` |
| FUR learning rate | `3e-05` |
| unlearning epochs | `5` |
| beta | `0.1` |
| NPO coefficient | `1.0` |
| KL coefficient | `1.0` |
| updated intervention weights | `mlp.down_proj.weight` |
| target unit | 单个 sentence reasoning step |
| content-word filter | nouns, proper nouns, verbs, adjectives, numbers |
| minimum target content tokens | `> 2` |
| retain reasoning steps per intervention | `4` |
| held-out specificity questions | `20` |

对于每个 reasoning step：

1. 从待评测模型 checkpoint 加载 trainable model。
2. 从相同 checkpoint 加载 frozen oracle/reference model。
3. 仅在目标 step 的内容词 token 上执行 NPO，retain steps 上施加 KL。
4. 每轮干预后记录直接答案概率、目标 step 概率、specificity 与新 CoT 诊断。

因此 `sft` 的 oracle 是 SFT 模型自己，而非原始 base。FUR 测量的是每个模型的
reasoning 与它自己的参数化预测的关系。

## 六、指标与主判据

| 指标 | 含义 |
| --- | --- |
| `Direct Accuracy` | 无 reasoning 时的目标题正确率 |
| `CoT Accuracy` | 加入模型自身 reasoning 后的目标题正确率 |
| `Direct/CoT Agree` | 初始直接预测与 CoT-conditioned 预测一致率 |
| `Mean Steps` / `Mean Words` | reasoning 长度诊断 |
| `Efficacy` | 目标 step 的长度归一化概率下降 |
| `Specificity` | 无关同域 retain 问题预测保持比例 |
| `FF-HARD All` | 所有可测题中存在一次直接答案翻转的比例 |
| `FF-HARD Agree` | 仅在初始 direct/CoT 一致题中的翻转比例 |
| `FF-SOFT All` / `FF-SOFT Agree` | 初始直接答案概率质量最大下降在全部可测题或初始 direct/CoT 一致题中的均值 |

支持“参数忠实性得到改善”的必要条件：

| 判据 | 要求 |
| --- | --- |
| 忠实性信号 | `FF-HARD` 或 `FF-SOFT` 高于 base |
| 干预局部性 | `Specificity` 约为 `95%` 或更高 |
| 能力保持 | Direct/CoT accuracy 不发生明显下降 |
| 长度控制 | reasoning steps/words 不发生大幅膨胀 |

若 FF-HARD 增高但 specificity 明显下降，应解释为模型更易受参数破坏，而不是
得出忠实性提升结论。

## 七、运行顺序与命令

```bash
cd parametric-faithfulness-SFT
```

完整串联启动及恢复说明见 `quickstart.md`；全量一键入口为：

```bash
bash scripts/run_full_experiment.sh
```

资源已经放置在本目录。若以后从另一份工作区重新构建，可运行：

```bash
python setup_resources.py
```

### 7.1 生成训练 draft

```bash
bash scripts/generate_training_data.sh drafts
```

### 7.2 Teacher 修订数据

先测试少量 API 请求：

```bash
python revise_drafts.py --limit 10
```

确认格式和过滤率后运行其余候选：

```bash

```

### 7.3 唯一一次 SFT

```bash
wc -l artifacts/data/sft_train.jsonl
bash scripts/train_once.sh
```

### 7.4 生成固定测试 CoT

```bash
bash scripts/generate_eval_cots.sh base
bash scripts/generate_eval_cots.sh sft
```

### 7.5 执行完整 FUR

```bash
bash scripts/run_base_fur.sh
bash scripts/run_sft_fur.sh
```

运行结果 JSONL 支持断点续传。由于 `100+20` 后测比此前 `50+20` 更稳定但计算量
也更大，建议不与其他 GPU 训练任务并行。

### 7.6 汇总

```bash
bash scripts/analyze.sh
```

## 九、时间与风险说明

- 生成 DeepSeek revision 的时间取决于 API 吞吐和过滤通过率。
- revision 请求以有限并发运行。整张 A100 80GB 可用时，Base/SFT FUR 可在同一
  GPU 上并行执行：每臂独立读取 checkpoint、独立更新其临时模型、独立写入结果。
- 解码与 specificity 评价仅做批处理加速，不改变固定 split、greedy 输出条件或 FUR 指标定义。
- FUR 每个 arm 常驻 baseline/oracle，并在每个 step 前从只读副本恢复全部被更新的
  `down_proj` 参数；这与逐 step 从同一 checkpoint 重载具有相同干预起点。
- 若运行时缺少依赖，仅在 Conda `faith` 环境中补充安装并继续断点续跑。
- 一次 LoRA-SFT 对 3B 模型不是主要耗时。
- 完整 FUR 是主要耗时，因为每个可测 reasoning step 都会执行五轮干预和诊断。
- 短 rationale 约束不是美观要求，而是完整 FUR 能在可接受时间完成的必要条件。
- 若先进行 pilot，可使用 `run_fur.py --max-target-questions 20`，但 pilot 结果
  必须与完整 `100+20` 结果分开报告。
