# CoT 与 ToT 参数忠实度实验协议

## 1. 实验目的

本实验在 `OpenBookQA` 与 `ARC-Challenge` 上比较 `Llama-3.2-3B-Instruct`
生成的单路径 CoT 与多路径 ToT 的参数忠实度。测量方法沿用 FUR：删除 reasoning 所编码的信息后，
若无 reasoning 的模型答案发生改变，则该 reasoning 至少包含一条与参数决策
相关的路径。

## 2. 环境与资源

| 项目 | 设置 |
| --- | --- |
| conda 环境 | `faith`；后台脚本直接调用该环境的 `bin/python`，避免非交互 `conda activate` 卡住 |
| GPU | NVIDIA A100-SXM4-80GB |
| 模型 | `meta-llama/Llama-3.2-3B-Instruct`，运行时使用项目内 `local_models/Llama-3.2-3B-Instruct` 快照 |
| 数据集 | `allenai/openbookqa` 与 `allenai/ai2_arc` (`ARC-Challenge`)；正式运行读取项目内 `local_datasets/` |
| 工作目录 | `parametric-faithfulness-ToT/` |
| Hugging Face 鉴权 | 模型与数据集已落盘，正式脚本不读取或传递 token |
| Hub 访问 | 正式脚本设置 `HF_HUB_OFFLINE=1` 和 `TRANSFORMERS_OFFLINE=1` |

## 3. 问题划分

从 OpenBookQA test 生成 70 个 reasoning 样本，在固定 `seed=1001` 洗牌后：

| 子集 | 数量 | 用途 |
| --- | ---: | --- |
| target set | 50 | 对 reasoning 做 unlearning 并测量忠实度 |
| retain/specificity set | 20 | 测量参数修改对无关同域问题的影响 |

划分清单保存为：

```text
splits/openbookqa_seed1001_n50_retain20.json
```

CoT 和正式 ToT 必须匹配该清单，否则执行器终止，避免比较不同问题子集。
若运行中断，已完成的 unlearning 结果按目标 ID 跳过，已完整写出的 ToT
路径缓存按对应 split、样本数和 seed 复用。

ARC-Challenge test 按相同协议生成 120 个 reasoning 样本：

| 子集 | 数量 | 用途 |
| --- | ---: | --- |
| target set | 100 | CoT/ToT 参数忠实度主比较 |
| retain/specificity set | 20 | 同域 specificity |

ARC 划分清单为 `splits/arc_challenge_seed1001_n100_retain20.json`。

## 4. CoT 实验

CoT 生成采用论文设置：

| 参数 | 值 |
| --- | --- |
| decoding | greedy |
| temperature | `0.0` |
| maximum new tokens | `300` |
| segmentation | NLTK sentence tokenization |

对每题的每个有效句子单独训练一个 unlearned model。有效目标是至少含有两个
可遗忘 content tokens 的句子。

## 5. ToT 候选设计与选择

### 5.1 Sample-Select ToT

| 参数 | 值 |
| --- | --- |
| complete paths per question | `5` |
| temperature | `0.7` |
| top-p | `0.9` |
| maximum new tokens per path | `300` |
| selection score | `max_y P(y | q, path)` |

### 5.2 Beam-Prune ToT

| 参数 | 值 |
| --- | --- |
| tree depth | `3` |
| branch factor | `2` |
| beam width | `3` |
| max tokens per thought expansion | `72` |
| temperature / top-p | `0.7 / 0.9` |
| pruning score | `max_y P(y | q, partial path)` |

### 5.3 选择协议

两种方法先在 validation 的小规模对照集合上运行，不使用 test 选择 ToT 类型。
比较顺序为 validation accuracy、平均 winning confidence、平均路径数。胜出
方法随后生成 test 的 70 条正式 ToT reasoning 样本。

## 6. Unlearning 设置

CoT、ToT-selected 和 ToT-union 共用下列参数：

| 参数 | 值 |
| --- | --- |
| method | `npo_KL` |
| learning rate | `3e-05` |
| epochs per forget operation | `5` |
| beta | `0.1` |
| npo coefficient | `1.0` |
| KL coefficient | `1.0` |
| reference policy | `fine_tuned` base model |
| trainable parameters | all Transformer `mlp.down_proj.weight` |
| POS-filtered targets | `VERB`, `NUM`, `ADJ`, `NOUN`, `PROPN` |
| retain steps per operation | `4` |

### 6.1 ToT-selected

对获胜路径按句切分，每个句子单独 unlearn。此实验与 CoT 的 granularity 一致，
构成主对比。

### 6.2 ToT-union

每题将树中生成的不同候选路径作为一个联合 forget set，在同一 unlearning
模型中依次执行其路径目标。该实验回答“整棵搜索树承载的信息是否比最终路径更
影响直接答案”。由于目标不再是单句，其单步 efficacy 不与 CoT 直接比较。

## 7. 记录指标

| 指标 | 统计方式 |
| --- | --- |
| `Efficacy` | `1 - p_after(step) / p_before(step)`，仅 CoT 与 ToT-selected 主报 |
| `Specificity` | retain set 中 unlearning 前后直接答案相同的比例 |
| `FF-HARD` | 题级：任一步遗忘后直接答案翻转的比例 |
| `FF-SOFT` | 初始直接答案的概率质量下降均值 |
| `Path Diversity` | ToT 缓存中的 distinct paths 数量和答案投票熵 |
| `Gen (MMLU)` | 论文 Table 1 的零样本 MMLU post-unlearning accuracy；用 10 个目标问题的补充实验获得 |
| `Post-CoT Agree` | 遗忘后新生成 reasoning 与无 reasoning 答案一致率，仅作为扩展诊断指标 |

## 8. 执行命令

验证两种 ToT：

```bash
conda activate faith
cd parametric-faithfulness-ToT
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
python tot_generation.py --model_name local_models/Llama-3.2-3B-Instruct \
  --dataset openbook --split validation --mode compare \
  --max_instances 30 --output_dir final_tree_ToT
```

运行 CoT 正式实验：

```bash
bash scripts/run_openbook_cot_full.sh
```

根据 validation 选出的 `<MODE>` 运行正式 ToT：

```bash
bash scripts/run_openbook_tot_full.sh <MODE>
```

也可以使用选择后自动衔接正式运行的脚本：

```bash
bash scripts/run_openbook_tot_select_and_full.sh
```

主对比完成后，可单独执行联合遗忘补充实验：

```bash
bash scripts/run_openbook_tot_union.sh <MODE>
```

运行 ARC-Challenge 主对比：

```bash
bash scripts/run_arc_cot_full.sh
bash scripts/run_arc_tot_select_and_full.sh
```

ARC 的 ToT 路径生成可与 OpenBookQA 实验并行。由于 ToT unlearning 需要同时
加载 trainable 与 oracle 模型，ARC-ToT 脚本在进入该阶段前检查可用显存；
低于 `30000 MiB` 时每五分钟等待一次，以避免四条线路在峰值阶段同时占满
A100 显存。

按论文 Table 1 补充 ARC 的 `Gen (MMLU)` 测量：

```bash
bash scripts/run_arc_mmlu_supplement.sh <MODE>
bash scripts/run_openbook_mmlu_supplement.sh <MODE>
```

两条 MMLU 补充脚本在主实验完成后再执行；它们需要 `lm_eval` 读取公开 MMLU
任务，因此不强制离线模式，其输出分别写入 `final_result_CoT_mmlu/` 与
`final_result_ToT_mmlu/` 并由分析流水线自动合并。

生成可在运行中重复刷新的论文式表格与图表：

```bash
python analysis_pipeline.py --output_dir final_analysis/LLaMA-3-3B
```

该命令自动发现 `final_result_CoT/`、`final_result_ToT/` 与
`final_result_ToT_union/` 中已有结果，输出 `metrics.csv/json`、
`table_controls.md/tex`、`table_faithfulness.md/tex`，以及 PNG/PDF 图：
`eff_spec_faithfulness`、`faithfulness_comparison`、
`unlearning_trajectories`、`tot_mode_selection`。
